# Floors and ceilings, with a reason for each bound that is not obvious.
#
# This file is NOT the pinned environment -- `requirements.lock.txt` is, with 177
# exact versions captured from the machine that produced the reported results.
# The split is deliberate: CI installs from this file so it keeps working as the
# ecosystem moves, while the lock file is what someone reproducing the numbers
# should install. `python scripts/freeze_env.py` regenerates the lock file.
#
# torch >= 2.3 is a hard floor, not a preference: the trainer uses the
# device-agnostic AMP API (torch.amp.GradScaler(device_type, ...)), which does
# not exist before 2.3. On 2.0-2.2 the training loop raises AttributeError on
# the first step -- inside the booked window, which is the worst place to find out.
torch>=2.3,<3.0
transformers>=4.40,<6.0
tokenizers>=0.19
scikit-learn>=1.3,<2.0

# Declared explicitly although scikit-learn already pulls it in: the paired
# intervals and the exact sign test in evaluation/aggregate.py are ours, not
# sklearn's, so relying on a transitive dependency for them would be a silent
# way to break the report's statistics.
scipy>=1.10,<2.0
pandas>=2.0,<4.0
numpy>=1.24,<3.0
matplotlib>=3.7,<4.0
PyYAML>=6.0,<7.0
tqdm>=4.65
tabulate>=0.9
